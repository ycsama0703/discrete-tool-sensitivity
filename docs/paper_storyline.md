# 论文故事线：离散工具调用的敏感度认证为什么骗人，以及唯一零漏报的检测方法

> 这是论文的**叙事主线**——从"我们怎么发现"到"为什么理论对"到"为什么筛查器是唯一零漏报的"。
> 它把 `paper_framework.md` 的各个探针（Phase-0 → 阶段 F）串成一个连贯的故事，
> 并补上金融叙事的血肉。写作纪律见 §末尾。

---

## 第一幕：我们怎么发现的（金融场景的意外）

### 场景：一个本该可靠的金融数据调用

想象一个 LLM agent 在回答"**AAPL 最近一个季度的 EPS 是多少？**"。它调用 findata 的
`get_fundamentals` 工具，填 `period="quarter"`。一切正常。

但 agent 有时会填成 `period="fy"`（财年）——或者更隐蔽地填 `period="all"`（两个都要）。
这个调用**仍然 schema 合法**（`fy`/`all` 都在 enum 里）、**返回 HTTP 200**、**没有任何
报错**。但返回的 EPS 从 `2.04`（季度）变成 `6.11`（财年）——**输出跳变 66–72%**。

**这是金融场景里最危险的一类错误**：不是调用失败（会报错、会被发现），而是调用"成功"
但**返回了错误口径的数据**。agent 和用户都以为拿到了正确数字，实际上口径错了。

### 我们问的第一个问题

一个做 agent 可靠性的人会问：**这个输出对输入扰动有多敏感？** 现有答案是连续
Lipschitz 界 `S_cont(ε) = L·ε`——假设错误落在输入的连续邻域内。

但我们发现：`period` 是**离散**的。从 `quarter` 到 `fy` 没有"连续路径"，是一个 token
的直接替换。对离散替换 `z→z'`：
- 连续空间里 `ε=0`（没有连续变化）→ **`S_cont(0) = 0`**
- 但实际输出跳变 66–72%

**关键洞察**：连续界不是"漏掉"这个误差，而是**主动宣称"零误差、很稳"**。这比没有认证
更糟——agent 会**过度信任**一个其实会跳变的输出。这是"认证会骗人"的虚假安全感问题。

### 为什么这不是"连续性被破坏"

我们**不**声称离散性破坏了连续性——在有限集上任何函数都连续，用离散度量时界是有信息
的。问题是**错误模型选错了**：领域把离散参数选择建模成"量化"（quantization，一个有界
小误差，能被扰动抑制吸收）。但语义枚举**不是连续网格**——`quarter` 和 `fy` 是**不同的
问题**，不是相邻的格子。所以覆盖这个情况的误差模型根本不存在。

## 第二幕：理论——为什么连续界测不到，什么才测得到

### 核心对象

对工具调用 `x = (c, z)`，`c` 连续（日期、阈值）、`z` 离散（ticker、period、unit）：

```
S_cont(ε) = sup_{||c'-c||≤ε} d_Y(f(c',z), f(c,z)) ≈ L·ε   # 连续界
D_G       = max_{z'∈N_G(z)} d_Y(f(c,z'), f(c,z))            # 离散最坏跃迁
S_mix(ε)  = L_G·ε + D_G                                     # 混合界
```

对离散替换 `z→z'`：连续界 `ε=0 → S_cont(0)=0`，漏掉 `D_G`；混合界 `S_mix(0)=D_G` 覆盖。

**理论贡献（修复后）**：`S_mix(0) = D_G(0) > 0 = L·0` 的结构结论——连续界在 `ε→0` 时
无法覆盖离散跃迁。这是**条件性、结构性的理论**，不是深刻的新数学定理——它用现成的三角
不等式 + Lipschitz，把"连续界漏离散"变成严格的、可验证的表述。

### 决策几何：什么决定翻转

哪个量决定决策翻转取决于**决策类型**：
- **序关系决策**（top-k、两两比较）：由 `ρ = σ_r/σ_q` 决定
- **绝对阈值决策**：由 `κ = |μ_r|/σ_q` 决定
- 连续界对两者都报零

实测：`corr(ρ, flip) = +0.851`，而 `corr(jump, flip)` 仅 `+0.110`——**排名结构**预测
翻转，**输出跳变幅度**几乎不预测。这是"决策几何"而非"输出幅度"在起作用。

### 机制层：为什么 LLM 会填错

阶段 A 证明：模型能理解任务语义，但**没能把它绑定到工具参数**。一个非绑定的输出偏好
（symbol 偏好）压倒了正确的绑定信号。绑定在模糊输入上不充分——这是填错的根源。

## 第三幕：实验——证据链如何接上理论

### 从纯数据到真实 agent（证据链的递进）

| 阶段 | 测什么 | 关键结果 |
|---|---|---|
| **Phase-0** | 离散跃迁存在（纯数据，$0） | 输出跳 66–72%，100% schema-valid |
| **3.2 generator relevance** | 真实 LLM 会犯这些错误 | 弱模型 12–18.75%；"强模型 0%" 已被阶段 G 推翻 |
| **3.3–3.4 混合敏感度** | 连续界漏、混合界盖 | 8→20 symbol，全 PASS |
| **3.5 端到端** | 筛查器能否解决（MC 模拟） | 12% 决策错误 → 0% |
| **3.6–3.11 决策几何** | 翻转的充要条件可推导 | corr(ρ,flip)=+0.851，4 宇宙 48 格 |
| **3.12 CertDR baseline** | 现有认证方法 | 只认证 2/48，而 14/48 真稳 |
| **阶段 A/C** | 机制：绑定不充分 | 绑定只支配 10%，符号偏好 92% |
| **阶段 D** | 真实 agent 端到端 | 真实错误 24.5–28%，筛查器 100%→0% |
| **阶段 E** | baseline family 对比 | 只有枚举筛查器精确（prec/recall 100%） |
| **阶段 F** | 自我检查 vs 枚举（三阶梯） | L3 错误定位 qwen 仅 4.6% |
| **阶段 G** | 跨规模/跨厂商扫描（12 配置） | 错误率**从不离开 25.9–38.2%**；L3 召回 0.0–89.8% 无规律 |
| **阶段 H** | 多模型投票 baseline | 投票 30.0%，**差于最好单模型**；错误相关 φ=+0.53~0.68 |
| **3.18 Daloopa** | 外部效度（真实商用检索） | 170 个真实错误 100% 跳变 >1%，界全报零 |

### 证据链如何接上理论

- **Phase-0 → 理论**：纯数据证明离散跃迁存在且规模可观（66–72%），理论给出为什么
  连续界漏掉它（`S_cont(0)=0`）。
- **generator relevance → 机制**：真实 LLM 会犯这些错误，机制层（阶段 A）解释为什么
  （绑定不充分）。
- **决策几何 → 理论**：`ρ` 预测翻转（+0.851）而 `jump` 不预测（+0.110），证明"决策
  几何"而非"输出幅度"在起作用——这是理论的核心预测。
- **阶段 D/E/F → 筛查器价值**：真实 agent 填错（D）、只有枚举零漏报（E）、自我检查
  不可靠（F）——三层证据共同支撑"枚举筛查器是唯一零漏报保证"。

## 第四幕：为什么枚举筛查器是唯一零漏报的（阶段 E + F 的收束）

### 阶段 E：对比 5 个方法 family

在同一任务（top-3 by EPS）上问：谁能检测到"agent 填错 → 决策翻"？

| 方法 | precision | recall |
|---|---|---|
| F1 连续界 L·ε | — | 0% |
| F2 SAFER | 77% | 62% |
| F3 Monte Carlo | 88% | 94% |
| F4 Gecko（合法性） | — | 0% |
| **我们的枚举筛查器** | **100%** | **100%** |

> **注（Stage-I 修正）**：此表的 100%/100% 是 identity（`our_flags = true_flip`），不是测量。
> Stage-I 实测：决策错误召回 **100%**（零漏报），精度 **5–20%**，flag 率 50–92%（数据属性）。
> 所以筛查器的价值主张是"**唯一零漏报保证**"，不是"唯一精确方法"。

只有枚举筛查器保证零漏报。其他 family 给**界**（F1/F2）或**随机估计**（F3）或**合法性检查**
（F4），只有枚举**重算决策**能保证不漏掉决策翻转。

### 阶段 F：回答"为什么不直接让 LLM 自己检查？"

审稿人第一个异议是"为什么不直接让 LLM 检查自己的 tool call？"三阶梯实验回答：

| 阶梯 | 模型需要的能力 | qwen recall | qwen precision |
|---|---|---|---|
| **L1 值比较** | 字符串比较（答案喂给它） | 100% | 99% |
| **L2 语义判断** | 靠自己的理解判断 | 100% | 65% |
| **L3 错误定位** | 知道有问题，找出哪错 | **4.6%** | 8.9% |
| 枚举筛查器（对比） | 不依赖模型 | 100% | 100% |

**L3 是最有力的数字**：即使告诉模型"筛查器 flag 了你的调用有问题"，它也只有 4.6%
能定位出是 `period` 错。这正是论文的核心洞察——**"即使模型知道了哪里有问题，也不一定
能够识别出来到底哪里错了"**。

### 为什么枚举筛查器在所有阶梯都是 100%

因为它**不依赖模型**——它枚举所有 period 值（|S|≈3）重算决策，不管模型填什么。它
不需要模型知道错在哪，它自己把所有可能值都试一遍。

### 阶段 G：规模和厂商都救不了（12 个配置）

把同一套阶梯扩到 7B → 前沿、5 个厂商、12 个配置：

| | period 错误率 |
|---|---|
| 7B–12B 本地模型 | 27.3 – 29.8% |
| 70–72B | 25.9 – 38.2% |
| 当代商用（5 厂商） | 29.5 – 37.9% |

**12 个配置全部落在 25.9–38.2%**。claude-sonnet-5 是 36.5%，**高于**本地 7B 的 27.3%。
10 倍参数、约两个代际、开源到前沿——都没让这个错误变少。

而自我检查的 L3 召回横跨 **0.0%（gpt-6-luna）到 89.8%（qwen3.8-flash）**，且与规模、
代际、厂商都不相关。同一家族放大 10 倍可以变好（qwen 4.6%→68.6%）也可以变坏
（llama 63.8%→6.8%）。

**第三种失败模式**：gemini-3.8-flash 有 **100/400** 次发出格式完全正确但**整个省略
`period`** 的调用——schema 合法、零报错、API 静默套默认值。比填错更隐蔽，而筛查器照样
拦得住。

### 阶段 H：多模型投票也救不了

"那跑三个模型投票呢？"——投票错误率 **30.0%**，比最好的单模型（27.3%）还差。原因是
投票的前提（错误独立）不成立：三个模型两两错误相关 φ=+0.53~0.68，**三个全错的概率是
独立假设的 7.4 倍**，而且它们通常在同一个错误值上达成一致。

**核心对比（贯穿全篇）**：任何**经过模型判断**的检测器都会继承模型的绑定缺陷——
- **自我检查**依赖失败的绑定 → L3 在 0–90% 间无规律波动
- **多模型投票**共享同一缺陷 → 30.0%，差于单模型
- **换更大/更新/更贵的模型** → 错误率纹丝不动（25.9–38.2%）
- **外部枚举**（筛查器）不依赖模型 → 所有配置零漏报（决策错误召回 100%）

## 一句话故事线

> **离散参数替换是 schema 合法但语义错误，连续误差模型测不到它（`S_cont(0)=0` 却跳变
> 66–72%）；它也不会随模型变强而消失（12 个配置，7B 到前沿，错误率始终 25.9–38.2%）。
> 它也无法靠"写好描述"消除——因为真实描述只能提示"认真检查"，而"认真检查"无效（模型不知道
> 检查什么），要降低错误必须告诉模型"哪里可能错"，而"哪里可能错"只能靠枚举探测发现。
> 枚举筛查器不依赖"认真检查"（无效）也不依赖"针对性提示"（需要先验知识），它枚举离散邻域
> 重算决策，既测量敏感度（翻转由 ρ 决定，G6：+0.851），也揭示哪里需要写进描述——它是"写好描述"
> 的前提，也是唯一不依赖"知道哪里会出错"的方法。**

## 第四幕补充：为什么筛查器是"写好描述"的前提（I1 = Stage-J）

> 实验编号以 `EXPERIMENT_REGISTRY.md` 为准。

### I1（Stage-J）：接口 vs 模型缺陷的四档消融

把"接口 vs 模型缺陷"做成四档消融（qwen2.5-7b，各 400 case）：

| 变体 | 改动 | 错误率 |
|---|---|---|
| S0 | 非必填（泛化描述） | 28.0% |
| S1 | period 必填 | 27.3% |
| S2 | 必填 + 详细描述（点名测试集字段） | 0.0% |
| S3 | 必填 + 通用描述（去泄漏） | 1.8% |

**三个事实**：required 无效（S0→S1 不变）；描述质量完全消除错误（S1→S2 归零）；S2 不是泄漏
（S3 通用描述也达 1.8%）。

**深层逻辑**：S2/S3 的"修好"依赖**预先知道模型会在哪里出错**（强调"quarter 和 fy 不同"这个
动作本身，就预设了你已经知道歧义在哪）。真实描述只能提示"认真检查"，但"认真检查"无效——模型
不知道检查什么（28%）。要降低错误必须告诉模型"哪里可能错"，而"哪里可能错"只能靠枚举探测
（=筛查器）。**筛查器是"写好描述"的前提，不是替代。**

**S2/S3 的正确地位是 bonus**：它们证明"模型在被告知歧义后能 detect"——排除"模型能力"解释，
把问题锁定在"不知道检查哪里"，**加固主线**而非否定主线。

### ρ 与筛查器 flag 率的关系（G6/G7，已有，不是新实验）

G6/G7 用的就是真实 findata 数据（tau_universe，4 宇宙 × 12 字段 = 48 格），ρ 预测翻转：
corr +0.851（jump 只有 +0.110）。ρ 高的宇宙 flag 率也高，这解释了 S4 中 flag 率在 50–92%
之间的差异（TECH 的 ρ=0.75，CONSUMER 的 ρ=0.43）。

> 更正（2026-09-26）：之前这里写的"Stage-K 把决策几何从合成推广到真实，+0.539"是错的。
> G6/G7 本来就是真实数据；Stage-K（G9）只是同一份数据上的粗化重复，已作废。

**待补（I2，计划中）**：阶梯 L2.5——把筛查器的输出（哪个参数敏感、各取值的后果）告诉模型，
但不给答案，看它能否改对。这是"筛查器是写好描述的前提"目前唯一没有实验支撑的一环。

## 金融元素如何补全叙事

### 为什么选金融（仪器，不是目的）

金融是**最自然的舞台**，因为：
1. **口径错误是致命的**：`quarter` vs `fy` 的 EPS 差 66–72%，一个 agent 用错口径做
   投资决策，可能基于错误数字下单。
2. **schema 合法掩盖错误**：`fy`/`all` 都在 enum 里，返回 HTTP 200，没有报错——这是
   金融数据 API 的常态，也是最危险的（错误不可见）。
3. **决策是量化的**：top-3 by EPS、阈值判断——金融决策天然是离散的（买/卖/持有），
   正好暴露"决策几何"。

### 我们如何发现的（叙事钩子）

不是从理论出发，而是从**一个具体的金融调用**出发：agent 回答"AAPL 最近一个季度的
EPS"，填了 `period="fy"`，返回 6.11 而不是 2.04——**没人报错，但数字错了**。这个
意外引出了整个研究：为什么一个 schema 合法的调用会静默地给出错误口径的数据？

### 实验如何接上理论（金融的具体化）

- **Phase-0**：在 findata 上实测 `period=quarter→fy` 的 EPS 跳变（2.04→6.11，66–72%）
- **决策几何**：top-3 by EPS 是序关系决策，由 `ρ` 决定翻转——金融决策的具体化
- **阶段 D**：真实 agent 在模糊问题上填错 `period`（"current assets" 等），筛查器拦截
- **阶段 F**：自我检查在错误定位上失败（L3 4.6%）——连模型自己都救不了自己

## 写作纪律（沿用 paper_framework）

- 不写"Lipschitz 预设连续性"——LipsLev 在 Levenshtein 距离上定义 Lipschitz 常数。
- 不写"certifying 离散替换是未探索的"——CertDR、SAFER、ℓ₀-top-k 直接反驳。
- 不写"我们修复 CertDR"——共模扰动只恢复 48 格中的 1 格，worst-case 界在这里就是
  错的工具。
- 金融是**仪器**，不是目的——别把论文写成"金融 agent 可靠性"，那是另一篇论文。
- 标 ○ 的引用（未自核方法节）在引用前必须自核。
