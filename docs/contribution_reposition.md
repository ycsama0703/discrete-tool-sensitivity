# 论文核心贡献的价值如何体现（重新定位）

> 2026-09-25。Stage-J 结果（描述能修好错误）表面削弱了"筛查器是唯一可靠方法"的叙事，
> 但暴露了更深的逻辑：**写好描述需要先验知识，而先验知识只能来自枚举探测（=筛查器）**。
> 本文档重新定位论文的核心贡献。

---

## 1. 旧叙事（已死）

> 模型有 25.9–38.2% 的绑定错误，枚举筛查器是唯一能精确检测的方法。

**为什么死**：Stage-J 的 S2/S3 证明详细描述能把错误从 28% 压到 1.8%。如果写好描述就能修，
筛查器在防一个能轻易修掉的接口问题。

## 2. 新叙事（更强）

> **离散参数错误无法靠"写好描述"消除，因为写好描述需要知道模型会在哪里出错，而"哪里会出错"只能靠
> 枚举探测发现——这正是筛查器在做的事。筛查器不是"接口缺陷的替代"，而是"接口缺陷的检测前提"。**

**关键逻辑链**：
1. **真实描述只能做到**：列枚举值 + 提示"认真检查"（S0 那种）。
   > `period`: 报告期间。可选值：quarter（季度）、fy（财年）、all（全部）。请认真检查，确保选择正确。
   它列了枚举值 + 提示认真检查，但**没有强调任何特定歧义**——因为作者不知道哪里有歧义。
2. **"认真检查"无效**，因为模型不知道要检查什么。模型填 `all` 时不觉得自己错：`all` 在 enum 里、
   schema 合法、语义上"两个都要"看似合理。你告诉它认真检查，它检查了，还是觉得 `all` 对。
   （S0 就是这种泛化描述，错误率 **28%**。）
3. **要降低错误，必须告诉模型"哪里可能错"**（如"quarter 和 fy 是不同的东西"）。
4. **但"哪里可能错"你预先不知道**——强调"quarter 和 fy 不同"这个动作本身，就预设了你已经知道
   歧义在哪。一个不知道模型会在 `period` 上翻错的作者，不会想到写这句话。
5. **"哪里可能错"只能靠枚举探测发现**——枚举所有值、重算决策、看哪里翻转。
6. **枚举探测 = 筛查器**。

**筛查器的价值：它不需要"知道哪里可能错"，它枚举所有值重算决策。** 它不依赖"认真检查"（无效），
也不依赖"针对性提示"（需要先验知识）——它直接枚举，看决策是否翻转。

### S2/S3 的正确地位：bonus，不是主线判据

**S2/S3 不是"接口能修好，筛查器没必要"的证据，恰恰相反，它们加强主线。**

S2/S3 测的是："我已经明确告诉你哪里可能出问题了（quarter 和 fy 是不同的），你（模型）能不能
detect？如果错了能不能改？"这是一个**更强的测试**——给了模型"作弊级"帮助，看它能不能做对。
结果 S2/S3 压到 0–1.8% → **模型在"被告知歧义"的情况下确实能 detect 并改对。**

**这为什么加强主线？** 主线是"模型不知道哪里会出错，所以需要筛查器"。S3 证明"模型在知道哪里出错时
能 detect"——恰恰说明：模型**有能力** detect（不是模型笨），但**不知道要 detect 什么**（不知道歧义
在哪）。所以问题不在"模型能力"，而在"**模型不知道检查哪里**"，而"知道检查哪里"只能靠枚举探测
（=筛查器）。**S3 把"模型能力问题"排除掉了，把问题精确锁定在"不知道检查哪里"上——这是对主线的加固。**

**反事实**：如果 S2/S3 压不下去（模型被告知歧义还是错）→ 那才是"模型能力问题"，主线反而被削弱。
但 S2/S3 压下去了 → **排除"模型能力"，锁定"不知道检查哪里"** → **主线被加强**。S2/S3 压到 0–1.8%
是主线想要的理想结果，不是坏消息。

## 4. 价值如何体现——三个转变

### 转变一：从"筛查器是终点"到"筛查器是前提"
旧：筛查器是最终防线（防 27% 错误）。
新：筛查器是"写好描述"的前提——它先测出哪里敏感，描述才能写好；而它本身不依赖先验知识。

### 转变二：从"防错误"到"测敏感度"
旧：筛查器检测决策错误。
新：筛查器**测量**"这个决策有多依赖 period"（flag 率 50–92% 是数据属性，不是缺陷）。
这既是检测手段，也是 schema 设计的指导工具。

### 转变三：从"绑定缺陷"到"不知道检查哪里"的困境
旧：模型绑定失败是根源。
新：**根本困境是"不知道模型会在哪里出错"**——真实描述只能提示"认真检查"，但"认真检查"无效
（模型不知道检查什么），而"哪里可能错"只能靠枚举探测发现。筛查器解决的是这个困境，不是"模型笨"。
**S2/S3 证明模型有能力 detect（排除"模型能力"），把问题锁定在"不知道检查哪里"——这是对主线的加固，
不是否定。**

## 5. 一个需要诚实面对的点

审稿人可能说："那论文的贡献就是'枚举探测指导 schema 设计'，筛查器本身不是终点。"

**回应**：这正是论文应该拥抱的定位。论文的贡献不是"筛查器是终点"，而是"**离散参数敏感度需要
枚举探测才能被理解和修复**"——筛查器既是检测手段，也是 schema 设计的指导工具。这个定位比
"筛查器是唯一可靠方法"更真实、更站得住。
