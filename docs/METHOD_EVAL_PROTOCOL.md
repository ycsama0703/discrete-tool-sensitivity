## 0. 被测方法（我们的方法，先写清楚）

**枚举筛查器（ENUM）**：agent 发出的工具调用要喂给一个下游决策时，
**由理论自动决定在哪里查，全程不做人工设置**（2026-09-27 按用户的思路重写）：

| 步骤 | 做什么 | 理论依据 | 已单独验证过 |
|---|---|---|---|
| **1. 按类型分流** | 从 schema 类型区分连续参数和离散参数（enum）；连续参数交给连续界处理，**离散参数进入第 2 步** | S_mix：离散替换时 S_cont(0)=0，但 D_G>0 | P1–P3 |
| **2. 找跳变点（离线，每个端点只做一次）** | 对每个离散参数的每对取值，实测输出跳变 D_G；**D_G≈0 的参数或取值对直接排除**（例如 fundamentals 上的 `statement`） | D_G 的定义 | S5 |
| **3. 决策门（在线）** | 对剩下的参数，一次只改一个：其余参数保持模型填的值，逐个取值调用并重算决策，用**精确翻转条件**判断；ρ/κ 用来排优先级（S8） | 决策几何 G6/G7 | G6/G7 |

- 决策在剩余取值下都不变 → 放行；否则**报警**：不放行，交给用户确认，或暂不输出。记录每次报警由哪个参数触发。
- 这三步以前是**分开验证**的，本协议第一次把它们作为**完整流水线**来测；此前的实验都是人工选定了 period。
- 枚举范围由理论和接口决定，不依赖"错误会出在哪里"的事后知识 → 这是它和 I1 S2/S3 描述的本质区别。
- 延伸（不在本协议范围内）：第 2 步如果直接测跳变的形状，而不只看 schema 类型，就能发现"看起来连续、实际会跳变"的参数，例如日期在财年边界上的跳变（X3）。

**保证的范围**：只有一个 enum 参数出错时，放行出去的决策**不会因为这个错误而出错**（零漏报）。
**不保证**：自由文本参数的错误（symbol）、选错工具或字段、多个参数同时出错。
**变体 ENUM-joint**：枚举所有 enum 参数的笛卡尔积，覆盖多参数同时出错的情况；只报成本和覆盖率，作为对照。
**决策由谁来做**：S7 主实验里，决策都由**明确的代码**完成（取前 3 名、阈值筛选），这种情况下筛查器可以精确重算。"模型自己读数据、自己给出答案"的情况单独放在 **S7-B 子实验**里（见 §1b）。

**辅助量**：ρ = σ_r/σ_q（序关系决策）、κ = |μ_r|/σ_q（阈值决策），来自 G6/G7。它们给出一个连续的"风险分"，用于 S8 的预判规则，也用来解释报警率为什么高或低。

## 1. 数据集 D-DEC（新建）

**为什么要新建**：S4 用的是 20 只科技股、20 个问题模板，而且这些问题问的多是资产负债表、现金流字段，findata 的 fundamentals 端点根本不返回这些字段，决策只能改用 EPS 来算，题目和决策对不上。D-DEC 的决策问题直接问 findata 能返回的字段。

| 维度 | 取值 | 说明 |
|---|---|---|
| 宇宙 | TECH / FIN_HEALTH / ENERGY_STAPLES / CONSUMER，各 20 只 | 沿用 `tau_universe.py`，findata 的 quarter/fy 数据已验证可用；ρ 在各宇宙间差异大（0.43–0.75），flag 率预计也会不同 |
| 字段 | revenue、gross_profit、operating_income、ebitda、net_income、eps | fundamentals 端点，quarter 和 fy 都有 |
| 决策类型 | **序关系**："哪 3 家最高？"<br>**阈值**："哪些公司超过 T？"（T 取基期分布的中位数，**写死在问题里**） | 对应 G7：序关系看 ρ，阈值看 κ |
| 期间意图 | 明确季度 / 明确年度 / **未说明**（按约定：未说明 = 最新季度） | 明确的题几乎不会错（P8），错误主要来自"未说明"；三层分开报 |

- **规模**：6 字段 × 2 决策 × 3 意图 = 36 个模板；× 4 宇宙 = **每个模型 144 个决策实例**。
- **调用**：每个实例里，agent 对 20 只股票各发一次工具调用 → **每个模型 2,880 次调用**。
- **接口**：沿用 S0 的 schema（和 B2/B3、I1 一致），模型看到的工具不变。
- **真值**：用正确的 period 从 findata 取数，再算决策。

### 返回值的读取规则（两种都报）
- **主规则 R-first**：读返回序列的第一条。这是 findata 的实际行为：`all` 的第一条恰好是最新季度。
- **压力规则 R-annual**：`all` 改为读序列里最新的一条年度或 TTM 记录，模拟其他 API 的返回约定。
  → 用来检验方法的表现**不依赖 findata 这个排序巧合**（2026-09-26 用户指出的问题）。

## 1b. S7-B 子实验：决策由模型做出（小规模）

**问题**：数据取回来之后，如果由模型自己读数字、给出决策，筛查器的零漏报保证还剩多少？

- **范围**：只用 CONSUMER 一个宇宙（报警率适中，放行的决策足够多，漏报和误报都能看到）× 36 个模板 = 36 个决策实例。
- **模型**：llama3.1-8b（本地，容易犯参数错误）、claude-sonnet-5（API，强模型）。**temperature=0**。
- **模型怎么做决策**：把问题连同一张"股票 → 取到的数值"表交给模型，要求它**只用固定格式作答**（取前 3 名：输出 3 个代码组成的 JSON 列表；阈值题：输出一个 JSON 列表）。这样比较两次回答时，就是严格的集合相等，不用判断两段自由文本是否同义。
- **筛查器（B 版）**：三步流水线的前两步不变；第 3 步改为：对每个候选取值，用该取值下取到的数值表**重新问模型一次**，比较答案；答案不全相同就报警。
- **真值**：用正确 period 下的数据，由代码算出正确决策。
- **额外报告的指标**：
  - **自身不一致率**：同一张表问两次，答案不同的比例。这是 B 版误报的来源之一。
  - **错误拆成两类**：参数错误导致的决策错误（筛查器负责），以及模型数据没错、但自己推理错了的决策错误（不在筛查器保证范围内，单独报）。
  - 和 A 版相比，误报率和成本各增加多少。
- **预注册**：
  - **H-B1**：放行出去的决策里，由参数错误导致的错误 = 0。
  - **H-B2**：误报率高于 A 版，而且高出来的部分能由"自身不一致率"解释。
  - **H-B3**：模型自己推理错的决策单独计数，不算作筛查器漏报，但必须报告。

## 2. 评测指标

把问题看作**选择性决策**：每个方法对每个决策实例给出"放行/报警"（或一个风险分），报警的实例不输出。

| 指标 | 定义 | 作用 |
|---|---|---|
| **覆盖率 Coverage** | 放行实例数 / 总实例数 | 越高越好用 |
| **选择性风险 Selective risk** | 放行实例里决策错误的比例 | **主指标**，越低越好 |
| **漏报数 / 决策错误召回** | 放行出去的决策错误数；被拦下的决策错误 / 全部决策错误 | 检验"零漏报"主张 |
| **精度** | 报警实例里真的出错的比例 | S4 暴露的短板 |
| **AURC** | 风险–覆盖率曲线下面积（只对输出连续分数的方法算） | 汇总曲线，越低越好 |
| **同覆盖率下的风险** | 在 ENUM 的覆盖率上，其他方法的选择性风险 | 二元方法之间的对比 |
| **参数层召回 / 精度** | 按参数错误（而非决策错误）算 | 和 B2/B3 的阶梯接得上 |
| **成本（S9）** | 每个决策额外的工具调用次数、LLM 调用次数、耗时；开缓存和不开缓存各报一次 | ENUM 的代价 |

- **统计**：按模板做聚类 bootstrap，报 95% 置信区间。
- **分层报告**：模型 × 宇宙 × 决策类型 × 期间意图 × 读取规则。

**列入相关工作、但不当基线的：**
- **LLMCert-T**（◐ 2510.03992）：给整个管线的失败率一个统计上界，不对单个决策报警，形式不同，只在相关工作里对比。
- **erase-and-check**（◐ 2309.02705）：结构上最接近我们（枚举后重算），但对象是有害 prompt 检测，这里没有对应的任务；在讨论里对照它的"枚举规模 → 误报上升"。
- **Agent-Sentry**（◐ 2603.22868）：看参数值的来源，针对注入攻击，威胁模型不同。

**公平性约束：**
- 所有方法看同一批 agent 调用、同一份真值、同一个测试集。
- SAFER 式方法的调用预算与 ENUM 相同。
- 需要阈值的方法只能在校准集上调。

## 4. 预注册假设（冻结后不改）

- **H1 零漏报**：ENUM 在每个模型 × 宇宙 × 决策类型 × 读取规则下，放行出去的决策错误数都 = 0。
- **H2 同覆盖率下最优**：在 ENUM 的覆盖率上，其余每个方法的选择性风险都 > 0；并且依赖模型判断的方法（自我验证、自一致性、强模型裁判、投票），风险在各模型之间的波动大于 ENUM。
- **H3 报警率可解释**：在宇宙 × 字段层面，ENUM 的报警率和 ρ（序关系）/ κ（阈值）正相关（Spearman > 0.5）。
- **H4 降低误报（S8）**：至少有一个变体在测试集上决策错误召回 ≥ 95%、精度至少是 ENUM 的 2 倍。
- **H5 不依赖排序巧合**：R-annual 读取规则下 H1 依然成立。

**什么结果会削弱我们：**
- 如果**强模型裁判**或 **CRC** 在全部模型上召回 ≥ 99%，而覆盖率高于 ENUM，那么 ENUM 的优势就只剩"不依赖模型、结果确定"和成本，论文要相应收窄。
- 如果 H3 不成立，决策几何就不能用来解释报警率。
