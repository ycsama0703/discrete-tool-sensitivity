## 一、现象层：离散参数敏感度存在

### 1.1 Phase-0 离散敏感度（`README_discrete_sensitivity.md`）
- **测什么**：findata 离散工具参数（period/unit/ticker）是否产生连续界测不到的输出跃迁。
- **结果**：`period=quarter→fy` 输出跳变 **66–72%**，100% schema-valid（API 接受、无报错）。
- **作用**：建立论文的现象基础——离散参数替换是 schema 合法但语义错误，连续 Lipschitz 界
  （`S_cont(0)=0`）测不到它。

### 1.2 决策几何（`README_decision_geometry.md`）
- **测什么**：哪个量决定决策翻转——输出跳变还是决策几何。
- **结果**（48 格）：
  - 序关系决策（top-k/两两比较）由 **ρ = σ_r/σ_q** 决定（+0.791）
  - 阈值决策（"> T"）由 **κ = |μ_r|/σ_q** 决定（+0.908）
  - 输出跳变对序关系几乎无预测（+0.11）
- **作用**：证明"决策翻转由决策几何决定，而非输出跳变幅度"。这是论文的核心机制主张，
  有 Policy Cliff / Non-adv Robustness / CertDR 理论背书。

### 1.3 决策几何在真实数据上验证（`README_stageK_decision_geometry_real.md`）
- **测什么**：ρ 是否在真实数据（4 宇宙 × 12 field）上预测 period 敏感度（筛查器 flag 的地方）。
- **结果**：corr(ρ, period-sensitive) = **+0.539**（48 个真实决策）；敏感决策平均 ρ=0.618，
  不敏感 0.275；4 个宇宙全部方向一致（+0.363 到 +0.668）。
- **作用**：**填补缺口 4**——决策几何不仅在合成数据上成立，在真实数据上也预测"哪些决策对 period
  敏感"。这把理论和筛查器接起来：ρ 解释了筛查器为什么 flag（决策几何决定），也解释了 Stage-I 的
  flag 率差异（ρ 高的宇宙 flag 率高）。

## 二、机制层：真实 agent 会犯这些错误

### 2.1 Stage-D 端到端（`README_stageD_agent_e2e.md`）
- **测什么**：真实 LLM agent（不是 Monte Carlo 模拟）是否真的填错 period。
- **结果**（3 模型，各 400 case）：
  - 真实错误率 **24.5–28%**（qwen 27.5%、llama 24.5%、gemma 28.0%）
  - 错误集中在模糊 quarter 问题（"current assets"、"cash from investing"、"shareholders' equity"）
  - 筛查器把决策错误从 100% 降到 **0%**（3 模型一致）
- **作用**：把 Phase-0 的"纯数据现象"升级为"真实 agent 行为"——真实 agent 在模糊问题上
  确实填错 period，且筛查器能拦截。

## 三、方法层：筛查器的价值

### 3.1 Stage-I 筛查器实测（`README_stageI_screener_measured.md`）
- **测什么**：枚举筛查器在真实模型输出上到底达到什么精度/召回。
- **结果**：
  - 决策错误召回 **100%**（零漏报）
  - 精度 **5–20%**（不是之前声称的 100%）
  - flag 率 50–92%，取决于 symbol 宇宙（数据属性，不是筛查器缺陷）
- **作用**：诚实测量筛查器。修正了"100%/100%"的 identity/oracle 错误。筛查器的价值主张
  从"唯一精确方法"改为"**唯一零漏报保证**"，flag 率是数据属性（测量 period 敏感度）。

### 3.2 Stage-J schema 消融（`README_stageJ_schema_ablation.md`）
- **测什么**：接口 vs 模型缺陷——改变 schema 必填性/描述质量，错误率怎么变。
- **结果**（qwen2.5-7b，各 400 case）：

  | 变体 | 改动 | 错误率 |
  |---|---|---|
  | S0 | 非必填（泛化描述） | **28.0%** |
  | S1 | period 必填 | **27.3%** |
  | S2 | 必填 + 详细描述（点名测试集字段） | **0.0%** |
  | S3 | 必填 + 通用描述（去泄漏） | **1.8%** |

- **作用**：这是论文核心贡献层的关键实验。三个结论：
  1. **required 无效**（S0→S1：28.0%→27.3%）——模型不是漏填，是填了 schema 合法的错误值 `all`。
  2. **描述质量完全消除错误**（S1→S2：27.3%→0.0%）。
  3. **S2 不是泄漏**（S3 通用描述也达 1.8%）。

  **深层逻辑**：S2/S3 的"修好"依赖**预先知道模型会在哪里出错**（强调"quarter 和 fy 不同"这个
  动作本身，就预设了你已经知道歧义在哪）。真实描述只能提示"认真检查"，但"认真检查"无效（模型
  不知道检查什么，28%）。要降低错误必须告诉模型"哪里可能错"，而"哪里可能错"只能靠枚举探测
  （=筛查器）。**筛查器是"写好描述"的前提，不是替代。**

  **S2/S3 的正确地位是 bonus**：它们证明"模型在被告知歧义后能 detect"——排除"模型能力"解释，
  把问题锁定在"不知道检查哪里"，**加固主线**而非否定主线。

## 四、替代方案层：为什么其他方法不行

### 4.1 Stage-E baseline family（`README_stageE_baseline_family.md`）
- **测什么**：5 个方法 family 谁能检测"agent 填错 → 决策翻"。
- **结果**：

  | 方法 | precision | recall |
  |---|---|---|
  | F1 连续界 L·ε | — | 0% |
  | F2 SAFER | 77% | 62% |
  | F3 Monte Carlo | 88% | 94% |
  | F4 Gecko（合法性） | — | 0% |
  | 枚举筛查器 | 100% | 100% |

- **注意**：Stage-I 已修正——枚举筛查器的 100%/100% 是 identity/oracle，实测是召回 100%、
  精度 5–20%。Stage-E 的表应标记为 identity，不是测量。
- **作用**：证明只有枚举筛查器精确（修正后：零漏报）。

### 4.2 Stage-F 自我检查（`README_stageF_selfcheck.md`）
- **测什么**：让填错的模型自己检查（三阶梯 L1/L2/L3），能否 detect。
- **结果**（3 模型）：

  | 模型 | L1 rec/pre | L2 rec/pre | L3 rec/pre |
  |---|---|---|---|
  | qwen2.5:7b | 100/99 | 100/65 | **4.6/8.9** |
  | llama3.1:8b | 100/30 | 100/28 | **60.6/24** |
  | gemma3:12b | 100/100 | 99/76 | **22.7/73** |
  | 筛查器 | 100/100 | 100/100 | 100/100 |

- **作用**：证明"让模型自己检查"不可靠——L1/L2 召回高但精度崩（cry wolf），L3 定位 qwen 仅
  4.6%。自我检查依赖失败的绑定能力，无法替代外部枚举。

### 4.3 Stage-G 跨规模/厂商（`README_stageG_openrouter.md`）
- **测什么**：12 个配置（7B→前沿、5 厂商），错误率和自我检查怎么变。
- **结果**：
  - 错误率**从不离开 25.9–38.2%**（claude-sonnet-5 36.5%，高于本地 7B 的 27.3%）
  - L3 召回横跨 **0.0%（gpt-6-luna）到 89.8%（qwen3.8-flash）**，与规模/代际/厂商无关
  - gemini-3.8-flash 有 100/400 次**省略 period**（schema 合法、静默套默认值）
- **作用**：证明"换更大/更新/更贵的模型"救不了——错误率纹丝不动，自我检查不可预测。

### 4.4 Stage-H 多模型投票（`README_stageH_voting.md`）
- **测什么**：跑三个模型投票能否降低错误。
- **结果**：投票错误率 **30.0%**，**差于最好单模型**（27.3%）。错误相关 φ=+0.53~0.68，
  三全错概率是独立假设的 **7.4 倍**。
- **作用**：证明"跑多个模型投票"也救不了——错误不独立，共享同一绑定缺陷。

## 五、外部效度

### 5.1 Daloopa 外部效度（`README_daloopa_external_validity.md`）
- **测什么**：现象在真实商用检索（Daloopa）上是否成立。
- **结果**：170 个真实 period 错误，100% 跳变 >1%，73% 超过 10%；连续 Lipschitz 界全报零。
- **作用**：证明离散参数错误在真实商用检索上也存在，且连续界测不到。

## 证据链总览

```
现象层        Phase-0: 离散参数 66-72% 跃迁, 连续界测不到
   ↓
机制层        决策几何: 翻转由 ρ 决定, 不是输出跳变 (+0.791 vs +0.11)
              Stage-K: ρ 在真实数据上预测 period 敏感度 (+0.539, 4 宇宙一致)
   ↓
真实 agent    Stage-D: 真实 agent 24.5-28% 填错, 筛查器 100%→0%
   ↓
筛查器价值    Stage-I: 零漏报保证, flag 率是数据属性
              Stage-J: 筛查器是"写好描述"的前提 (描述需先验知识, 先验知识只能来自枚举探测)
   ↓
替代方案全不行 Stage-E/F/G/H: 连续界/自我检查/换模型/投票都救不了
   ↓
外部效度      Daloopa: 现象在真实商用检索成立
```

## 核心贡献（一句话）

> **离散工具参数（schema enum）的敏感度无法靠"写好描述"消除，因为真实描述只能提示"认真检查"，
> 而"认真检查"无效——模型不知道要检查什么。要降低错误必须告诉模型"哪里可能错"，但"哪里可能错"
> 只能靠枚举探测发现。枚举筛查器不依赖"认真检查"（无效）也不依赖"针对性提示"（需要先验知识），
> 它枚举离散邻域重算决策，既测量敏感度，也揭示哪里需要写进描述——它是"写好描述"的前提。**
