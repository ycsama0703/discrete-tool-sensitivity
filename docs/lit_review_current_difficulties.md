## 0. Stage-J 最终结果（2026-09-25，决定性）

四档 schema 消融（qwen2.5-7b，各 400 case）：

| 变体 | 改动 | 错误率 | 错误值 |
|---|---|---|---|
| S0 | baseline（period 非必填） | **28.0%** | 全 `all` |
| S1 | period 必填 | **27.3%** | 全 `all` |
| S2 | 必填 + 详细描述（含指向测试集的提示） | **0.0%** | — |
| S3 | 必填 + 通用描述（去掉指向测试集的提示） | **1.8%** | 全 `all` |

**三个决定性结论：**
1. **`required` 约束无效**（S0→S1：28.0%→27.3%）。模型不是漏填，是填了 schema 合法的错误值 `all`。
2. **描述质量完全消除错误**（S1→S2：27.3%→0.0%）。
3. **S2 的 0% 不是泄漏**（S3 用通用描述也达 1.8%）。通用描述质量就能解决，不是"点名测试集字段"的提示。

**表面判读**：S1/S2/S3 都把错误率压到 ~10% 以下 → "绑定缺陷"大部分是接口缺陷。
**深层判读（本文档核心）**：S2/S3 的"修好"依赖**事后知识**（预先知道哪里会翻错才能写好描述），
真实世界写描述时不知道哪里会出问题。筛查器不需要这个先验知识——它是"写好描述"的前提。详见 §2。

## 1. 困难一：筛查器"高召回、低精度"（Stage-I 实测精度 5-20%）

### 现象
枚举筛查器决策错误召回 100%，但精度只有 5–20%（flag 率 50–92% 取决于 symbol 宇宙）。
之前声称的"100%/100%"是 identity/oracle，不是测量。

### 文献里别人怎么处理（精读结论）
- **erase-and-check（2309.02705）最直接**：明确讨论"安全 prompt 被误判为有害"的 FP，用 empirical
  精度（97-98%）约束，并指出**枚举规模增大 → 误报率上升**的机制（检查更多子序列 → 任一子序列误判
  概率累积）。**这正是我们"枚举离散邻域重算决策"的核心风险。**
- **Hybrid RS（2605.12876）明确说"flag 率是数据属性"**：ℓ₀ 文本预算 d_hybrid=0.33 反映"不安全
  prompt 改一两个 token 就翻转"的内在属性。**这是 22 篇里唯一触及我们"flag 率是数据属性"主张的。**
- **Agent-Sentry（2603.22868）**：三层级联把 LLM judge 调用压到 3.1%，报告 FPR（3.6% XGBoost /
  10.7% 规则版），讨论"过度约束牺牲灵活性"，用 ambiguous 中间态控制 FP。
- **Beyond Aggregate Risk（2607.24343）**：显式报告 over-intervention（shift 下 30.6%），讨论
  abstain vs revert 的 utility 权衡。
- **其余 6 篇**（SAFER/RanMASK/Text-CRS/LipsLev/RobustRAG/CluCERT）都**不讨论 FP**——它们报
  certified accuracy（保守下界），天然回避"过度警告"，代价是覆盖率下降。

### 我们的创新点（如何突出）
**不是"精确检测"，而是"零漏报保证 + 敏感度测量"。** 文献里只有 Hybrid RS 一篇触及"flag 率是数据
属性"，没人把"筛查器精度"和"flag 率是数据属性"分开讲。我们的独特主张：
> 枚举筛查器提供**零漏报保证**（决策错误召回 100%），代价是**过度警告率由数据的 period 敏感度决定**
> （50–92%）。这不是缺陷，是**测量**——它把"这个决策有多依赖 period"变成可量化指标。

**突出方式**：把 Stage-I 的"精度 5-20%"从"缺点"重构成"数据属性"，用 erase-and-check 的"枚举规模→
误报率"机制 + Hybrid RS 的"flag 率是数据属性"作背书。

## 2. 困难二：接口 vs 模型缺陷（Stage-J，已定论）

### 现象
S0 28.0% → S1 27.3% → S2 0.0% → S3 1.9%。描述质量完全消除错误，且不是泄漏。

### 文献里别人怎么处理（精读结论）
- **SilentProbe（2609.00035）最彻底**：证明"参数取值错误率主要由 schema 如何描述约束决定"，做了
  最干净的 schema 消融（把词汇提升进 enum，88/88→0/89），结论"修复是一行 schema，不是更好的模型"。
  区分"披露（模型能否选对值）vs 机器可读性（错误值能否被抓住）"两个可分离属性。
- **More Vulnerable（2506.21967）**：明确区分"参数描述缺失 vs 功能描述缺失"，结论"缺参数描述影响
  更大（最大降 4.2%）"，用 GPT-4 生成完整文档作基准、逐级删除控制 confound。
- **ToolRobustBench（2608.23635）**：A 族接口扰动（名字替换/描述抽象化/兄弟混淆），加别名后
  21/30→30/30——证明接口澄清能修复 S1 驱动的误选。
- **Butterfly Effects（2507.15296）**：工具文档 6 种扰动，结论"参数名幻觉是模型固有（FR<4%），
  其他失败是输入源驱动"。
- **LLMCert-T（2510.03992）**：关掉插入工具的确定性后处理（参数碰撞/同形字/说服线索），认证上界
  从 0.20 升到 0.33/0.37——证明 schema 形式是驱动因素。

**关键空白（精读确认）**：**没有一篇做"改变必填性（required↔optional）看错误率"的消融。**
SilentProbe 改 enum、More Vulnerable 删描述、ToolRobustBench 加别名，但必填性消融是空白。
**这正是 Stage-J 的 S0→S1 做的事。**

### 我们的创新点（如何突出）
**文献只警告了 schema confound，没人系统测它，更没人做必填性消融。** 我们的独特贡献：
> 把"接口 vs 模型缺陷"做成**四档消融**（S0 非必填 → S1 必填 → S2 详细描述 → S3 去泄漏），
> 分离出：required 约束无效（S0→S1 不变）、描述质量是决定性因素（S1→S2 归零）、
> 以及"描述是否泄漏测试集"（S2→S3）。

**但 Stage-J 表面上是坏消息，深层逻辑却救了论文**：S3 也压到 1.8%，表面看"通用描述质量就能解决"。
**但 S2/S3 的"修好"有一个隐藏前提：我们预先知道要写什么描述。**

- S2 的描述有效，是因为我们**已经知道**测试集里的模糊字段（`current assets`、`shareholders' equity`）。
- S3 的通用描述有效，是因为我们**已经知道** `quarter` vs `fy` 是核心歧义。

**现实里，写 schema 描述时根本不知道 agent 会在哪里翻错。** 这正是"翻错"的定义——如果知道哪里会
出问题，早就写好了。所以 S2/S3 是**用事后知识去写描述**，方法论上是泄漏（S2 点名测试集字段；S3 的
"quarter 和 fy 是不同的东西"也是从已知错误模式提炼的）。**S3 的 1.8% 不是真实世界错误率，而是
"在知道答案的情况下写描述"的错误率。** 真实世界错误率是"不知道哪里会出问题"的作者写出来的——28%（S0）。

**这如何把筛查器价值找回来**：筛查器（枚举离散邻域重算决策）**不需要知道哪里会出问题**——它枚举
所有 period 值、重算决策、看是否翻转。描述需要先验知识才能写好（真实世界不可靠），筛查器不需要
（真实世界可靠）。审稿人若说"先枚举测敏感度再写描述"，那恰恰证明筛查器是前提——测敏感度就是筛查器。

**论文核心主张（重新定位）**：
> **离散参数错误无法靠"写好描述"消除，因为写好描述需要知道哪里会出问题，而知道哪里会出问题只能靠
> 枚举探测——这正是筛查器在做的事。筛查器不是"接口缺陷的替代"，而是"接口缺陷的检测前提"。**

## 3. 理论困难：连续界 vs 离散跃迁（已解决，2026-09-21 重写）

### 现象
连续 Lipschitz 界 `S_cont(ε)=L·ε` 对离散替换报零，但输出跳变 66–72%。

### 文献里别人怎么处理（精读结论）
- **The Policy Cliff（2507.20150）**：有限集上连续性平凡成立，不稳定源自离散动作集上的 argmax。
  **推翻了我们的旧说法**（"离散破坏连续性"是空的），但给了更好基座。
- **Non-adv Robustness（2605.29816）**：把鲁棒性定义为 **margin 稳定性**（ρ 变号），margin shift
  框架 `ρ(x+δ)=ρ(x)+f`。**这是"ρ 预测翻转而非输出跳变"的最强背书。**
- **CertDR（2209.06691）**：用"间隔 vs 扰动上界"判定 Δ>0，豁免在位者，查询端留作未来工作。
- **2609.16599**：把 LLM 参数输出建模成 quantization（有界小误差）。**这是真正的靶子**——枚举
  参数不是细网格，替换不是舍入。
- **LipsLev（2501.13676）**：在 Levenshtein 距离上定义 Lipschitz 常数。**禁止我们写"Lipschitz
  预设连续性"。**

### 我们的创新点（如何突出）
**不是"连续界漏离散"（已知前提），而是"领域把离散参数建模成 quantization 是错的"。**
> 领域共识（2609.16599）把工具参数选择建模为 quantization——有界、小、可被扰动抑制吸收。
> 这个误差模型对语义枚举不成立：`quarter`→`fy` 不是舍入，是跳到另一个语义分支，输出动 66–72%。

**突出方式**：第一层从"连续界失效"（已被 Policy Cliff 推翻）改成"**quantization 误差模型错配**"
（有 2609.16599 逐字原文支撑）。这是文献里没人指出的。

## 4. 精读对"实验操作方式"的启示

22 篇论文的实验操作方式分四类，**没有一篇修改模型权重**：

| 类别 | 论文 | 操作 |
|---|---|---|
| 改 schema/接口 | SilentProbe、More Vulnerable、ToolRobustBench、Butterfly Effects、LLMCert-T | 改 enum/描述/别名/文档 |
| 改 prompt/上下文 | Gecko、Agent-Sentry、Beyond Aggregate Risk | 外部检测/校准层 |
| 改输入扰动 | CertDR、Non-adv、Policy Cliff | 随机替换/噪声/改 reward |
| 纯统计/理论 | LLMCert-T、TEE（2604.11581） | Clopper-Pearson、方差分解 |

**关键洞察**：文献全部是"黑盒操作"——改的是模型看到的东西，不是模型本身。这印证我们的方法定位：
- Stage-J（改 schema 必填性/描述）属于类别一，和 SilentProbe/More Vulnerable 同源，但**我们做了
  没人做的必填性消融**
- 枚举筛查器（枚举离散邻域重算决策）属于类别二——外部确定性方法，不依赖模型
- 决策几何理论（ρ 预测翻转）属于类别四——纯统计，不碰模型

## 5. 精读对"枚举可扩展性"的启示

**RobustRAG（2405.15556）最直接**：枚举中频关键词集合 W_C 的幂集，**|W_C|>15（2^15）就放弃认证
返回 τ=0**。这是对"枚举离散邻域可扩展性"的明确回答：可扩展性取决于"中频/不确定集合"的大小。

**erase-and-check**：枚举子序列，infusion 模式 O(n^d) 指数级，作者承认"长对抗序列不可行"。

**对我们的启示**：schema enum 场景，枚举规模 = 各 enum 参数取值数的笛卡尔积。RobustRAG 的"中频
集合阈值"思想可迁移：**只有"会导致决策翻转的临界组合"需要枚举，其余可剪枝**。我们的 |S|≈3 远小于
2^15，所以枚举完全可行——这是相对文本场景的优势。

## 6. 一个关键空白（我们的机会）

**22 篇论文全部处理自由文本/字符/段落，没有一篇处理结构化离散参数（schema enum）。**

我们的场景里"离散参数邻域"是有限、可枚举、无嵌入空间的符号集合——这比文本场景更简单（无语义破坏
问题），但也意味着**没有现成 baseline 可对标**，需要自建。同时，"flag 率是数据属性"主张在文献里
只有 Hybrid RS 一篇触及，是相对未被占用的叙事点。
